# Real PDAL verification — 2026-11-09

PDAL was pulled from the project's pinned Docker digest at the user's request. `verifyRuntime` reported **PDAL 2.8.4 (git 156082)** with readers.las and writers.copc. Earlier documentation that called this manifest 2.9.0 was inaccurate; the runtime output is authoritative.

Both actual integration runs passed, without mocking PDAL:

| Input | Points | Original bytes | Result |
| --- | ---: | ---: | --- |
| LAS 1.4, point format 6, EPSG:32640 | 10,000 | 301,679 | COPC verified, READY committed, Range 206, deletion successful |
| LAZ, point format 6, EPSG:32640 | 10,000 | 3,464 | COPC verified, READY committed, Range 206, deletion successful |

Fixtures were generated by PDAL readers.faux and writers.las, then uploaded via API to real MinIO. Real Redis/BullMQ dispatched the registered worker. The worker downloaded the original, inspected and converted it, verified the COPC info VLR and matching point counts, uploaded COPC, verified stored size and committed metadata/READY. The test also exercised part listing, repeated Complete, dataset listing/status, original/COPC Range reads, and repeated deletion. PostgreSQL migrations ran in disposable infrastructure; test containers were removed afterwards. No existing company/application databases or buckets were used.

This Docker installation could not bind application `/tmp`; using an existing checkout-local directory through TMPDIR resolved it. Reproduce:

```bash
mkdir -p .tmp
TMPDIR="$PWD/.tmp" REAL_PDAL=1 FIXTURE_FORMAT=LAS node scripts/integration.mjs
TMPDIR="$PWD/.tmp" REAL_PDAL=1 FIXTURE_FORMAT=LAZ node scripts/integration.mjs
```

The previously verified 671,811,028-byte multipart transfer used synthetic bytes and did not include real PDAL conversion. The new real conversion tests use small generated fixtures. Company data, large real-file processing, browser WebGL rendering, browser preflight and outage/stress acceptance remain separate checks; these results must not be described as proving those cases.

Frontend `.env` and `.env.example` now both specify `VITE_API_URL=http://localhost:3000/api/v1`; production frontend build succeeded with this setting. Backend and MinIO must allow the actual frontend origin for direct API/storage access.
